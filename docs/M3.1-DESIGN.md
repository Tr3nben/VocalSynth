# M3.1 design: take length, Record mode, gate -35 dB (v0.3.1)

Status: implemented and integrated 2026-10-21 (branch `m3.1-takes`, from `master` after v0.3.0; all gates green,
see docs/STATUS.md); review (realtime + correctness) done, fixes applied 2026-10-26 (section 12). Builds on
[docs/M3-DESIGN.md](M3-DESIGN.md) (section numbers "M3 x" below refer to it) and keeps all of its rules
(real-time safety, block-size invariance, capture tail, round trip at render time) unless this document says
otherwise. Segmentation tuning context: [docs/CORPUS.md](CORPUS.md), [docs/M2-DESIGN.md](M2-DESIGN.md) 10-11.

## 1. User feedback on 0.3.0 and what changes

FL Studio 2026 test (2026-10-21): timing, drag & drop, tempo changes, "Grab last 8 bars", CPU and stability
fine; Clean slightly better than Raw. **Problem:** background takes run far too long (e.g. 20 bars when he
wanted 8): mouse clicks and other noises after singing keep the take open, and a synced take always runs
from Play to Stop. He asks for

1. a setting "how many bars a background take records at most once it starts" (e.g. 16), then it is cut;
2. a direct **Record** mode: arm it, record exactly N bars (e.g. 8), so he knows where he is.

Also in this round: the gate default goes from -40 to **-35 dB** (corpus sweep: best gate; user: -35..-40 is
good), and a separate agent tunes the note segmentation (held notes split into extra notes on real singing:
note F1 ~0.33, precision 0.26; section 5).

| Area | 0.3.0 | 0.3.1 |
|---|---|---|
| Synced background take | Play .. Stop, one take | starts at the bar of its first note, cut after `takeMaxBars` bars (default 16); singing after the cut starts the next take |
| Free background take | first note .. 3 s pause | same, plus cut after `takeMaxBars` bars at the host tempo (else 120 BPM, 4/4) |
| Export end | synced: first bar line after the last event; free: last event | the bar line after the last **kept note** (Clean drops click / noise notes), never beyond the take end |
| Record mode | - | Record button: next bar line, exactly `recordBars` bars (default 8), stops by itself |
| Gate default | -40 dB | -35 dB |

## 2. Parameters (`plugin/Parameters.h`, done in the scaffold)

Appended after the M3 parameters with **version hint 3** (`params::takeLengthParameterVersionHint`): M1/M2
have hint 1, M3 hint 2 (released in 0.3.0), and JUCE orders AUv2 parameters by hint (M3 13). Existing IDs
are unchanged; old projects get the defaults (`migrateState` handles every missing parameter). Values and
tables come from the new core header `core/include/vocalsynth/CaptureMode.h` (static_assert-tied).

| ID | Name | Type | Values (index == core table / enum) | Default |
|---|---|---|---|---|
| `captureMode` | Capture Mode | choice | Background, Record (`CaptureMode`) | Background |
| `takeMaxBars` | Take Max Length | choice | Off, 4 bars, 8 bars, 16 bars, 32 bars (`takeMaxBarsChoices` 0/4/8/16/32) | 16 bars |
| `recordBars` | Record Length | choice | 1 bar, 2, 4, 8, 16, 32 bars (`recordBarsChoices`) | 8 bars |

No new non-parameter state (`CaptureState` stays version 1). The Record / Cancel button is a UI command, not a
parameter (an automatable "arm" would fire on project load and automation).

## 3. Background take length (`takeMaxBars`)

All rules of M3 5.2 stay; with `takeMaxBars` = Off nothing changes except the export end (3.4).

### 3.1 Synced takes (transport playing)

- The synced take still **opens** at the transport start (it must collect sounding notes and its timeline),
  but it is **anchored** at its first note: anchor bar X = the bar (`TakeTimeline::barAt`, with its snap
  tolerance) containing `max (startSample, h)`, where h = host-time estimate of the note-on =
  `estimatedSample - rtSeg` (rtSeg: 3.3). Then `startSample = max (transport start, start of bar X)`, so
  pre-roll noise before bar X can never pull the origin earlier and the take is at most N bars long.
- **Anchor candidates**: the take's first note-on with h >= startSample, or a note sounding at startSample (a
  synthetic note-on at the take start, or a real note-on with h < startSample) **only if** its note-off has
  h > startSample (or it is still on when the clock passes startSample + capture tail). A short note that
  ended before startSample (sung at the end of the previous take, emitted after the cut) never anchors.
- **Review fixes (0.3.1)**: (a) a candidate anchors only once it lasts the Clean ghost threshold
  `T = max (80 ms, minNoteLength)` (`TakeSegmenter::anchorMinNoteMs`): a note-on at its note-off if
  `h_off - h >= T`, or once it is still on at its emit sample + T + `detectionTailSeconds`; a note sounding at
  the start if `h_off >= startSample + T` (or still on at startSample + capture tail + T). Clicks and noise
  notes never decide bar X or the cut, and a note overhanging the cut by a few ms does not anchor the next take
  at X + N. (b) A bar line at most `anchorEarlyToleranceBeats` = 1/8 beat after h counts as the note's bar (a
  downbeat sung or estimated a little early; `barAt`'s 1/32 beat alone is 15.6 ms at 120 BPM). (c) A take
  opened with a limit that is never anchored and has no note of length >= T in its kept span (clicks only, or
  only the rest of a note that ended at the cut) is discarded like an empty take; its number is released.
  (d) The export origin of an anchored take with a limit is startSample (bar X), as for Record takes, so the
  file name and the length always match the counted bars (onset refinement can move the first note later).
  (e) Bar X is also set with limit Off (status line only; `maxBars` stays 0, the export ignores it).
- **Cut**: the take ends at the N-th bar line of the host grid after the start of bar X (counted as the
  timeline crosses them: a time-signature change or a loop wrap that re-anchors the grid counts the bar lines
  of the grid in force). The cut works exactly like a `newTake` marker at that sample in synced mode
  (M3 5.2): the old take gets `endSample` = cut, keeps collecting its capture tail and closes; the next
  synced take opens at the cut (kind automatic), sounding notes opened there. If that take finds an anchor at
  the cut (a note held across the bar line), it continues seamlessly at bar X+N; otherwise it anchors at the
  bar of its own first note ("singing after that starts a new take at its own bar"). A take without a
  note-on is discarded (unchanged rule).
- The limit in force when the take is anchored applies to it (`Take::maxBars`); a later change of
  `takeMaxBars` applies from the next take. "New take" restarts the count (new take, new anchor). Stop before
  the cut ends the take at Stop (unchanged). Grabs are not limited.
- The cut sample is where U reaches the bar line: `sampleAtBeats` on the segment in force. Every record up
  to that sample is in when `advanceTo` passes it, so the result is independent of the drain pattern and
  block-size invariant (transport changes on block boundaries, M3 4.3).

### 3.2 Free takes (transport stopped)

Limit `L = freeModeBarsToSamples (N, sampleRate, hostBpm)` (core helper, done: 4 quarter notes per bar at the
last known host bpm = `Take::freeBpm`, else 120). A free take that reaches `startSample + L` (review fix: A + L,
A = emit sample of the first note-on that lasts the ghost threshold T of 3.1 (a); a continued take: its start) is cut like a free manual split: synthetic note-offs at the cut in the old take; if notes
sound, the next free take opens at the cut with synthetic note-ons, else the segmenter waits for the next
note-on (`freeWaiting`). The 3 s gap rule stays.

### 3.3 Round trip used for segmenting (`rtSeg`)

The anchor needs host time, but the round trip is a render-time setting (M3 8). The worker therefore calls
`segmenter.setOffsetSettings (sources.readOffset())` before each drain; the segmenter computes
`rtSeg = computeRoundTripSamples (offset, maxBlockSize, sampleRate)` from its reset record (0 for Test
Pattern takes, M3 19.1 F5; default offset settings in core tests unless a test sets them). Changing the
offset later re-times exports as before; only the anchor bar of an already cut take was decided with the
old value (stated in the testing guide, harmless in practice: the offset is set once).

### 3.4 Export end of every take (`TakeRenderer`)

- **Synced background takes**: `endTick` = the first bar line (rendered time-signature map, as today) at or
  after the version's **last note-off tick** (bends / CCs after it do not extend the take; the trailing centre
  bend sits on that tick anyway), at most the tick of `endSample` (the cut / Stop). Clean removes click and
  noise notes (ghosts < 80 ms), so trailing noise-only bars disappear from the default export.
- **WAV** (`computeAudioSpan`): ends at the same bar line as the **Clean** render with the worker's WAV
  options (quantize off, = the default drag): `[sampleAtBeats (origin) + rt, sampleAtBeats (cleanEnd) + rt)`,
  at most `endSample + rt`. A Raw export may be longer than the WAV when Raw keeps trailing noise notes.
- **Free takes**: `endTick` = the version's last note-off tick (as 0.3.0, but notes only); WAV end = Clean's
  last note-off + `freeTailSeconds`, at most `endSample`.
- **Record takes**: no trimming (4.3).
- No note at all after Clean: unchanged (the take is listed only if Raw has a note; Clean then ends at 1 bar).
- Quantize never moves a note start to or past `endTick` (that start stays unquantized), so every note keeps
  >= 1 tick inside the take.

## 4. Record mode (`captureMode` = Record)

### 4.1 Behaviour

- **No background takes** (no synced Play..Stop takes, no free takes, "New take" disabled). The history keeps
  recording, so "Grab last ..." works as before. Switching Background -> Record closes an open background take
  at the switch (like a `newTake` marker, no new take opens); Record -> Background drops a pending arm, ends a
  running Record take there (kept, shorter) and resumes the background rules at that sample (playing: a
  synced take opens there, like `captureOn`).
- **Record** (button, `N = recordBars` at the moment of the click):
  - transport playing: the take starts at the **next bar line** of the host grid at or after the arm marker
    (a marker exactly on a bar line starts there). A position jump or loop wrap during the count-in
    recomputes it: the first bar line of the new grid at or after the jump. Status "Starts at bar X - n
    beats" (n = ceil of the beats left).
  - transport stopped: armed, "waits for Play"; it starts at the bar line where playback starts (the first
    bar line at or after the transport start; a start within the snap tolerance after a bar line counts as
    on it). Stopping during the count-in returns to waiting (still armed).
  - while recording: "Recording bar k/N"; the take ends by itself at the N-th bar line after X (counted as in
    3.1), i.e. it spans **exactly bars X .. X+N**; file name with bar X (`_Bar017_`). It then disarms (one
    shot).
  - Stop before the end: the take ends at Stop (kept, shorter, whole bars in the export). **Cancel** while
    armed disarms; Cancel while recording discards the take (nothing listed; the history still has it for a
    grab).
- Capture tail and round-trip compensation exactly as for synced takes (M3 5.2, 8): `endSample` = the end bar
  line, events collected until `endSample + compensationTailSamples`, compensated times clamped into
  `[startSample, endSample]`: notes sung before bar X are dropped / start at X, notes held over the end are
  clipped there. Sounding notes at X are opened (synthetic) as at any take start. `takeMaxBars` does not
  apply. Free mode (stopped, not armed): nothing is recorded as a take.

### 4.2 Data path (lock-free, timed by the audio clock)

```
CapturePanel Record / Cancel  -> captureTap.requestRecord (bars) / requestRecordCancel()   (atomics, any thread)
next beginBlock               -> marker recordArm (grabBars field = bars) / recordCancel at the block start
captureMode, takeMaxBars      -> CaptureSettingsInfo (settings record, on change) built per block by the processor
worker                        -> TakeSegmenter (rules 3, 4) -> getRecordStatus() published with CaptureStatus every step
```

The mode is in the stream (not read by the worker from the parameter), so a mode change is timed by the audio
clock and the segmenter stays deterministic and block-size invariant.

### 4.3 Export of Record takes

Origin = start of bar X (fixed, also if the first note comes later); `endTick` = ticks of
`U (endSample) - originBeats` (N bars when complete; a shortened take: the first bar line at or after its
end); WAV `[sampleAtBeats (originBeats) + rt, endSample + rt)`. Raw, Clean and the WAV have the same length,
so the dragged pattern / clip is exactly N bars.

## 11. Risks and open points

- The anchor uses the round trip at segment time (3.3); a later offset change does not move cuts.
- Count-in display after a loop wrap at the target bar line shows the predicted bar number; the file name uses
  the bar actually played (the wrapped one).
- A loop that is not a whole number of bars: Record counts bar lines of the grid as played, so the export may
  differ from N x bar length in beats (rare in FL, where loops follow the pattern length).
- The WAV follows Clean's end; a Raw drag can be longer than its WAV.
- Free-mode "bars" are 4/4 at the host bpm; with another time signature they are not the song's bars (free
  takes have no grid anyway).
